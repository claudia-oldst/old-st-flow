## Technical notes

- Pure moves and extractions only: no logic, query, RLS, or UI changes. Any file whose behaviour would have to change to fit under 250 lines is left alone and reported instead.
- Extracted components stay colocated in the owning feature folder; shared helpers go to the feature's existing helper module rather than a global `utils` dump.
- Existing tests (`parsePastedTitles`, timelog helpers, etc.) keep passing; where a pure helper is newly extracted and already covered indirectly, no new tests are added unless a helper had none and is non-trivial.
- Verification after each batch: `tsgo` typecheck, `vitest run`, production build, plus a preview smoke check of tickets, sprints, health, timelogs and the client portal.

## Sequencing

1. Pure helper/module extractions (hooks, parsers, edge functions) — lowest risk.
2. Presentational component splits per feature area, one area per batch with a typecheck between batches.
3. Final full verification (typecheck, tests, build) and a report of any file still over 250 lines with the reason.
